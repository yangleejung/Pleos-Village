# Pleos Village 구현 명세 v0.2

이 문서는 "무엇을, 어떤 규칙으로" 만드는지 정한다. 환경과 명령은 `CLAUDE.md`에 있다.
명세와 다르게 구현해야 하면, 먼저 사용자에게 묻고 이 문서를 고친다.
【확인 필요】는 아직 정하지 않았거나 SDK에서 확인해야 하는 항목이다.

v0.2 변경: 주민을 얻는 방식을 바꿨다. 주민마다 붙어 있던 숙제 같은 조건과 안전 조건을 없앴다. 이제 **그날의 운전 환경**이 어떤 주민을 만날지 정하고, **안전 점수(80점 이상)**가 만날 수 있는지를 정한다. 만남은 **공개된 확률과 천장(보장)**으로 정한다.

---

## 1. 앱이 하는 일

**한 문장**: 안전 운전으로 키우는 나만의 마을. 오늘의 운전이 어땠는지에 따라 마을에 찾아오는 주민이 달라진다.

**셀링 포인트**: 실제 운전이 그대로 주민과 마을이 된다. 차량 데이터(와이퍼, 전조등, 좌석 탑승, 핸들, 브레이크, 기어)가 재료이고, 사용자는 조작하지 않는다. 수집(도감, 확률, 천장)은 다음 운행을 기다리게 만드는 장치이고, 안전 점수는 규칙이다.

**고객과 니즈**: 1차 고객은 아반떼로 첫 차를 산 20·30대, 2차 고객은 아이와 함께 타는 가족. 페인포인트: 안전 운전 습관을 유지할 동기가 부족하다(운전점수 서비스는 점수와 그래프만 보여 주고 시간이 지나면 예전 습관으로 돌아간다. 보험 할인은 가입·갱신 때 한 번 온다). 니즈 1) 운행 직후의 확인: 정차하면 바로 안전 점수와 판정 결과를 보여 준다. 니즈 2) 계속 제시되는 목표: 못 만난 주민, 천장까지 남은 횟수, 마을 꾸미기가 다음 운행의 목표가 된다. 캐릭터와 수집은 보상의 형태이고, 첫 차에 대한 애착은 부수 효과다.

**2차 PT 시연에서 증명할 것 3개** (이것이 이 앱의 인수 기준이다)
1. 주행 중에는 앱 화면이 보이지 않는다.
2. 그날의 운전 환경이 주민을 정한다. (예: 와이퍼를 켜고 운전 → 비 주민 레이니)
3. 안전 점수가 80점 미만인 운행에서는 주민을 만나지 못한다. (예: 급한 핸들 조작 2번 + 급제동 1번 = 70점)

## 3. 용어 정의 (판정은 이 정의만 따른다)

| 용어 | 정의 |
|---|---|
| 주행 중 | 기어가 D 또는 R인 상태. N은 주행 시간에 넣지 않는다. |
| 정차 | 기어가 P인 상태. |
| 주행 구간 | 기어가 P에서 벗어난 때부터 다시 P가 될 때까지. |
| 운행 | 첫 주행 구간이 시작된 때부터, 기어 P가 `TRIP_END_GAP`(30분) 넘게 이어질 때까지. 30분 미만의 정차(휴게소, 충전)는 같은 운행이다. 앱이 시작될 때 기어가 P가 아니면 그때 운행을 시작한다. |
| 휴식 | 운행 안에서 `REST_MIN`(10분) 넘게 이어진 정차. |
| 연속 운전 시간 | 마지막 휴식(없으면 운행 시작) 이후의 주행 시간 합. 주간 운전 기록에만 쓴다. 안전 점수에는 쓰지 않는다. |
| 급한 핸들 조작 | 주행 중에 `HARSH_WINDOW`(1초) 안에 조향각이 `HARSH_ANGLE`(90도) 넘게 바뀐 경우. 한 번 감지하면 `HARSH_COOLDOWN`(3초) 동안 다시 세지 않는다. 속도 필터가 켜져 있으면 속도가 `SPEED_FILTER_KMH`(20) 미만일 때 무시한다(주차 조작). 에뮬레이터는 속도를 바꿀 수 없으므로 시연에서는 속도 필터를 끈다. |
| 급제동 | 주행 중에 브레이크 페달이 눌린 순간 (Vehicle SDK `Brake.registerBrakePedalStatus`는 눌림 여부만 준다, 페달 % 없음). 떼었다가 다시 눌러야 다시 센다. 속도 필터가 켜져 있으면 속도 `SPEED_FILTER_KMH`(20) 미만에서 무시한다. 【2026-11-14 구현 결정. 실차에서는 감속도 조건이 필요할 수 있다. 속도 값을 아직 읽지 않아, 속도를 모르면 거르지 않는다】 |
| 안전벨트 위반 | 주행 중에 어느 좌석이든 안전벨트 미착용 경고가 `BELT_GRACE`(10초) 넘게 켜져 있는 경우. **차량이 지원할 때만 쓴다.** Pleos 에뮬레이터 v2.1.0은 이 값을 지원하지 않는다(ERROR_NOT_SUPPORTED_PROPERTY). |
| 뒷좌석 탑승 | ROW_2 또는 ROW_3 좌석 중 하나 이상에 사람이 탄 상태. |
| 와이퍼 동작 | WiperState가 멈춤 상태가 아닌 값. 【확인 필요: WiperState enum 중 "동작"으로 볼 값】 |
| 하향등 켬 | LightState가 켜짐인 값. 【확인 필요: LightState enum 값】 |
| 성에 제거 켬 | 앞 또는 뒤 창 중 하나 이상의 성에 제거가 켜짐. |
| 시간 배율 | `DEMO_TIME_SCALE`. 주행 시간, 정차 시간, 운행 끊김 시간에 곱한다. 급한 핸들 조작의 1초, 안전벨트 유예 10초에는 곱하지 않는다(항상 실제 시간). 실차는 1, 시연은 60(실제 1초 = 1분). |

## 4. 안전 점수와 주민 판정

### 4.1 안전 점수
- 운행마다 100점에서 시작하고, "이번 운행에서 지금까지" 일어난 일로 깎는다. 0점 아래로는 내려가지 않는다.

| 항목 | 감점 |
|---|---|
| 급한 핸들 조작 | -10 / 번 |
| 급제동 | -10 / 번 |
| 안전벨트 위반 (차량이 지원할 때만) | -20 / 번 |

- 차량이 지원하지 않는 항목은 점수에서 빼고, 도착 요약에 "이 차량에서는 확인하지 않음"으로 표시한다.

### 4.2 판정 규칙
1. **판정 시점**: 기어가 P가 되는 순간(정차 시작)마다 판정한다. 충전 주민만 예외로, 충전을 시작한 순간에 판정한다.
2. **판정 운행**: 이번 운행의 주행 시간이 `MIN_TRIP_DRIVING`(10분) 이상이고 그 순간의 안전 점수가 `SCORE_PASS`(80점) 이상이면, 그 운행을 "판정 운행"으로 정한다.
3. **하루 한도**: 하루에 판정 운행은 최대 `DAILY_JUDGE_LIMIT`(2개)다. 한도를 넘은 운행은 판정하지 않고, 천장 횟수도 올리지 않는다. (기획서 원칙: 많이 달려도 더 얻지 않는다.)
4. **주민마다 운행당 1번**: 판정 운행에서, 각 주민은 그 주민의 환경(4.3)을 처음 채운 정차에서 한 번만 판정한다. 그 정차에서 안전 점수가 80점 미만이면 판정하지 않는다(점수는 운행 안에서 내려가기만 하므로, 그 운행에서는 더 판정하지 않는다).
5. **확률과 천장**: 주민마다 확률 p와 천장 N이 있다. 판정할 때 그 주민을 못 만난 횟수 m이 N-1이면 반드시 만난다. 아니면 확률 p로 만난다. 못 만나면 m을 1 올린다.
6. **한 번 만난 주민은 다시 판정하지 않는다.** (변형 주민은 범위 밖)
7. **지원하지 않는 데이터**가 필요한 주민은 판정하지 않고 도감에도 보여 주지 않는다 (check…Capabilities 결과 기준).
8. **확률과 천장은 설정 > "확률 정보"에 모두 공개한다** (도감에는 표시하지 않는다, 2026-11-14 결정). 결제로 주민을 주지 않는다. 주민은 판매하지 않는다.
9. 난수는 주입할 수 있는 `RandomSource`로 만든다. 테스트에서는 고정한다.

### 4.3 주민
도감에 보이는 문장은 "만나는 환경" 칸의 문장을 쓴다. 기획서 별지 1과 같게 한다.
주민 이름은 2026-11-14 팀 결정이다. 범위 밖의 위치 주민은 바다 = 웨이브(Wave), 산 = 우디(Woody)로 도감에 "출시 이후"로만 보인다. 문장에서 이름 뒤 조사는 받침으로 고른다(레이니가, 웨이브는).

| id | 주민 | 만나는 환경 (이번 운행에서) | 판정 기준 | 확률 | 천장 | 단계 |
|---|---|---|---|---|---|---|
| rain | 레이니 (비) | 와이퍼가 동작한 운행 | 와이퍼 동작 중의 주행 시간 합 ≥ `RAIN_ENV_MIN`(5분) | 40% | 3번째 | M1 |
| family | 해삐 (가족) | 뒷좌석에 사람이 탄 운행 | 뒷좌석 탑승 중의 주행 시간 합 ≥ `FAMILY_ENV_MIN`(10분) | 50% | 2번째 | M1 |
| night | 무니 (밤) | 하향등을 켜고 달린 운행 | 하향등을 켠 주행 시간 합 ≥ `NIGHT_ENV_MIN`(10분) | 30% | 4번째 | M1 |
| winter | 스노이 (겨울) | 성에 제거를 쓴 운행 | 성에 제거를 켠 주행 시간 합 ≥ `WINTER_ENV_MIN`(1분) | 30% | 4번째 | M1 |
| longtrip | 저니 (장거리) | 2시간 넘는 운행에서 중간에 쉰 운행 | 운행 주행 시간 ≥ `LONG_TRIP_MIN`(2시간), 휴식 1번 이상 | 50% | 2번째 | M2 |
| charge | 재피 (충전) | 충전한 날 (전기차) | 운행 중 정차에서 충전을 시작함 | 30% | 4번째 | M2 |

## 5. 안전 운전 포인트 (주민과 별도)

- 판정 운행이 정해진 정차에서, 그때의 안전 점수로 한 번 준다.
  - 90~100점: +20
  - 80~89점: +10
  - 80점 미만: 없음
- 판정 운행만 포인트를 받으므로 하루 최대 40점이다.
- 주행 거리나 주행 시간으로는 포인트를 주지 않는다.
- 포인트는 꾸미기 아이템을 얻는 데 쓴다 (M2). 주민은 포인트로 얻을 수 없다.
- 【확인 필요: 점수 값은 팀이 정한다】

## 6. 동작 흐름

### 6.1 상태 기계
```
대기(운행 없음, P) --기어 P 아님--> 주행 (새 운행 시작)
주행 --기어 P--> 정차      : 정차 처리 (6.2)
정차 --기어 P 아님--> 주행  : 정차가 REST_MIN 넘었으면 휴식 +1, 연속 운전 시간 = 0
정차 --P가 TRIP_END_GAP 넘게 유지--> 대기 : 운행 종료, 운행 기록 저장
```
- 운행 종료는 타이머에 기대지 않는다. 다음 기어 변화가 올 때 "직전 정차가 30분을 넘었는지"를 보고 처리한다(프로세스가 죽어도 맞게 동작). 디버그 메뉴의 "운행 종료" 버튼으로도 끝낼 수 있다.
- 시간 누적: 차량 값이 바뀔 때마다, 직전 상태가 이어진 시간(시간 배율 적용)을 해당 누적값(와이퍼 동작 시간, 뒷좌석 탑승 시간, 하향등 시간, 성에 제거 시간)에 더한다.
- 시간은 `SystemClock.elapsedRealtime()` 기준으로 잰다. 날짜(하루 판정 한도)만 실제 날짜를 쓴다.
- 운행 상태는 값이 바뀔 때마다, 그리고 주행 중 30초마다 저장한다.

### 6.2 정차 처리 (기어가 P가 된 순간)
1. 이번 운행의 누적값을 확정하고 안전 점수를 계산한다.
2. 아직 판정 운행이 아니면, 판정 운행 조건(4.2의 2·3)을 확인한다. 조건을 채우면 판정 운행으로 정하고, 하루 판정 횟수를 1 올리고, 포인트를 준다(5장).
3. 판정 운행이면, 환경을 처음 채운 주민을 판정한다(4.2의 4·5).
4. "도착 요약"(StopSummary)을 만든다: 안전 점수와 감점 내역, 만난 주민, 못 만난 주민과 천장까지 남은 횟수, 판정하지 않은 이유(10분 미만 / 80점 미만 / 오늘 판정 2번을 다 씀), 포인트.
5. 저장하고 "아직 보지 않음"으로 표시한다.

### 6.3 화면 표시 규칙
- Pleos에서 앱은 앱 창에 계속 떠 있다. 주행 중에는 플랫폼이 앱 화면을 가리고(`distractionOptimized`를 선언하지 않았으므로), 정차하면 다시 보인다. 에뮬레이터에서는 기어를 D로 바꾸면 주행 규제가 켜진다.
- **앱 화면이 보이는 상태에서 정차하면** 도착 요약 화면으로 이동한다.
- **앱 화면이 보이지 않으면** 앱이 스스로 화면을 띄우지 않는다. 다음에 앱을 열 때 보지 않은 도착 요약을 먼저 보여 준다.
- 주행 중에는 애니메이션과 화면 갱신을 멈춘다.
- 알림은 Foreground Service의 상시 알림 1개만 쓴다(중요도 LOW, 소리·팝업 없음). 새 주민 알림은 쓰지 않는다. 【확인 필요: Pleos 알림 정책】

| `vehicle/` | `VehicleDataSource`(있음). M1에서 브레이크와 주행 규제(`CarUxRestrictionsManager`)를 추가. 안전벨트 경고는 지원하는 차량에서만 쓴다. M2에서 충전 상태를 추가. | 조향각과 브레이크는 StateFlow 말고 이벤트 흐름(SharedFlow, 버퍼 있음)으로도 낸다. StateFlow는 중간 값을 버려서 급한 핸들 조작을 놓칠 수 있다. |
| `domain/` | `TripRecorder`(상태 기계와 누적), `SafetyScore`, `Residents`(주민 정의 표), `Encounter`(판정 운행, 하루 한도, 확률, 천장), `Points`, `TimeSource`(시간 배율), `RandomSource` | **Android import 금지.** 순수 Kotlin이라서 JVM 단위 테스트로 검증한다. |
| `data/` | `Repository` 인터페이스와 구현 | M1은 앱 내부 저장소의 JSON 파일. 라이브러리는 Kotlin 1.9.0과 맞는 것을 고른다. M2에서 필요하면 Room으로 바꾼다. |
| `service/` | `RecordingService`(Foreground Service: VehicleDataSource → TripRecorder → Repository), `BootReceiver`(부팅 시 서비스 시작) | 【확인 필요: Android 14의 Foreground Service type, 부팅 시 시작 제한, Pleos 심사 기준】 |
| `ui/` | 화면들(8장), 내비게이션 | Compose |

**저장 항목**: 현재 운행 상태, 지난 운행 요약(최근 50개), 주민별 상태(만남 여부, 만난 날짜, 못 만난 횟수 m), 날짜별 판정 횟수, 마을 배치, 포인트, 보지 않은 도착 요약, 설정(시간 배율, 속도 필터).

**데이터 흐름**: VehicleDataSource → TripRecorder → (StopSummary, 주민 상태) → Repository → 화면(StateFlow)

## 10. 시연 시나리오 (= 인수 기준)

준비: 디버그 메뉴에서 시간 배율 60×, 속도 필터 끔, 데이터 초기화, 오늘 판정 횟수 초기화. `adb forward tcp:8088 tcp:8088`.
시연은 확률에 기대지 않는다. "시연 데이터 불러오기"로 천장 직전 상태(레이니 2번 놓침, 해삐 1번 놓침, 저니 1번 놓침)를 만든다. 그러면 다음 판정에서 반드시 만난다.

**A. 레이니(비)와 해삐(가족) (M1)**
1. 시연 데이터를 불러온다.
2. Virtual Console: 운전석(ROW_1_LEFT)과 뒷좌석(ROW_2_LEFT)을 탑승으로 바꾼다.
3. Virtual Console: 기어 D → **앱이 유휴 화면(마을·시계)으로 바뀌고 터치가 막히는지 확인.**
4. Virtual Console: 와이퍼를 켠다. 15초 기다린다(= 15분).
5. Virtual Console: 기어 P → **도착 요약에 안전 점수 100점, 레이니, 해삐, 포인트 +20이 보인다.**
6. "마을 보기" → 두 주민의 집이 보인다. 도감에서 두 주민이 "만남"으로 보인다. 설정 > 확률 정보에 확률과 천장이 보인다.

**B. 안전 점수 미달 (M1)**
1. 데이터를 초기화하고 시연 데이터를 불러온 뒤, A의 2~4를 한다. 단, 주행 중에 조향각을 1초 안에 90도 넘게 2번 바꾸고, 브레이크 페달을 80%로 1번 밟는다.
2. 기어 P → **"안전 점수 70점 · 80점 이상이어야 주민을 만날 수 있어요"가 보이고, 주민은 오지 않는다.** 못 만난 횟수(천장 진행)는 그대로다.

**C. 저니(장거리) (M2)**
1. 시연 데이터를 불러온다.
2. 기어 D로 110초(= 1시간 50분) → P로 15초(= 15분, 휴식) → D로 20초(= 20분) → P.
3. **저니가 온다** (운행 2시간 10분, 휴식 1번).

**D. 하루 한도 (M2)**
1. 오늘 판정 운행을 2개 채운 상태에서 A를 한 번 더 한다.
2. **"오늘은 주민을 2번 만날 기회를 다 썼어요"가 보이고, 판정하지 않는다.**

## 11. 테스트

- `domain/`에 JVM 단위 테스트를 쓴다.
  - 안전 점수: 감점 계산, 80점 경계(80 통과, 70 실패), 지원하지 않는 항목 제외.
  - 판정: 10분 미만 운행 제외, 하루 한도, 주민마다 운행당 1번, 이미 만난 주민 제외.
  - 확률과 천장: 고정 난수로 성공·실패, 천장 횟수에서 반드시 만남, 못 만난 횟수 증가.
  - 환경: 각 주민의 판정 기준 경계값(예: 와이퍼 4분/5분), 운행 끊김(30분 정차), 시간 배율.
- 실행: `.\gradlew.bat :automotive:testDebugUnitTest` (에뮬레이터가 필요 없다).
- 마일스톤마다 10장의 시나리오를 에뮬레이터에서 확인한다.

## 12. 기획서와 맞춰야 하는 약속 (PT에서 어기면 안 된다)

- 주행 중에는 소리와 알림이 없다. 화면은 조작할 수 없는 유휴 화면(마을·시계·길 안내)만 보인다 (2026-11-14 결정).
- 안전 점수 80점 이상인 운행에서만 주민을 만난다.
- 확률과 천장을 설정 > "확률 정보"에 모두 공개한다(도감에는 표시하지 않음). 결제로 주민을 주지 않는다. 주민은 판매하지 않는다.
- 판정은 하루 2번까지다. 주행 거리로 보상하지 않는다.
- 차량이 지원하지 않는 데이터가 필요한 주민과 감점 항목은 뺀다.
- 위치를 수집하지 않는다. 데이터는 차량 안에만 저장한다.
- 세로형과 가로형 화면의 기능이 같다.
- 시동과 함께 자동으로 기록한다. 운전자는 아무것도 조작하지 않는다.
- 주민의 환경 문장, 확률, 천장은 기획서 별지 1과 같다.

## 13. 확인 필요 목록

1. 앱 화면이 없을 때 Foreground Service가 차량 값을 받는가 (M0) → 안 되면 7장 구조를 바꾼다.
2. 부팅 시 서비스를 자동으로 시작할 수 있는가. Android 14의 Foreground Service type과 부팅 시작 제한 (M0).
3. WiperState, LightState enum 중 "켜짐"으로 볼 값.
4. 브레이크 페달 값의 형식.
5. 급한 핸들 조작·급제동 기준값 (실차 데이터 없음).
6. 실제 차량에서 안전벨트 미착용 경고를 읽을 수 있는가 (에뮬레이터는 지원하지 않음).
7. Pleos 알림 정책 (새 주민 알림을 쓸 수 있는가).
8. Pleos의 확률 공개 규정을 설정 > 확률 정보 표시로 채울 수 있는가 (도감에서는 뺐다).
9. 포인트 점수 값, 확률·천장 값 (팀 결정).
10. 같은 주민을 다시 만날 수 있는가, 변형 주민을 언제 넣는가 (팀 결정).
11. 주민 그림 담당과 스타일 (팀 결정).
