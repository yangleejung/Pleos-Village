# Pleos Village 화면 설계 v0.1

기능 규칙은 `docs/SPEC.md`, 이 문서는 "어디에, 어떻게 보여 주는지"를 정한다.
목표: 모든 기능을 넣는다. 그러면서도 정차 중 짧은 시간에 가족이 함께 보고 바로 이해할 수 있어야 한다.

시안 그림은 `docs/design/`에 있다: `flow.png`(앱이 하는 일 3단계), `screen1_arrival.png`(도착 요약), `screen2_village.png`(마을), `screen3_dex.png`(도감), `screen4_portrait.png`(좁은 배치), `screen5_exchange.png`(이웃 교류, 앱에는 넣지 않음), `screen6_decorate.png`(꾸미기). 시안의 소스는 `docs/design/mockups.html`이다. 색, 그림자, 주민·집·나무·분수의 SVG 좌표를 그대로 Compose Canvas로 옮긴다. 스타일 규칙과 부품 구현법은 `docs/design/REFERENCES.md`에 있다. 배치와 동작은 이 문서를 따르고, 모양과 색은 시안을 따른다.

## 0. 모든 화면의 원칙

1. **한 화면에 주인공은 하나다.** 도착 요약은 만남 결과, 마을은 마을 그림, 도감은 주민 카드가 주인공이다. 나머지는 작게 둔다.
2. **3초 안에 핵심이 보여야 한다.** 숫자는 크게, 설명은 한 줄로 쓴다.
3. **손가락 하나로 모든 기능을 쓸 수 있어야 한다.** 길게 누르기와 두 손가락 동작은 보조로만 쓴다(같은 기능을 버튼으로도 제공).
4. **터치 대상은 76dp 이상이다** (Android for Cars 기준). 【확인 필요: Pleos 가이드의 수치】
5. **명암비 4.5:1 이상, 터치 반응 0.25초 이내** (Pleos 기준). 무거운 작업은 메인 스레드에서 하지 않는다.
6. **같은 굵기의 선으로 그린 파스텔 화면이 기본이다.** 모든 그림과 UI 테두리는 2dp 짙은 남보라(#3D3B52) 선, 평평한 파스텔 색, 둥근 제목 글꼴(Jua). 큰 면은 차가운 파스텔(연보라, 하늘, 민트), 분홍·노랑은 작은 곳에만 쓴다. 그림자, 그라데이션, 흐린 색 원, 질감, 이모지는 쓰지 않는다. 밤(시스템 야간 모드)에는 REFERENCES.md 2장의 밤 색을 쓴다.
7. **주행 규제가 켜지면 어느 화면이든 유휴 화면(4.2, 마을·시계·길 안내 카드)으로 바꾸고 터치로 다른 화면에 갈 수 없다.** 소리는 쓰지 않는다. 유휴 화면의 주민은 걷는다 (2026-11-14 결정, `distractionOptimized` 선언). 다른 화면의 연출(도착 요약 등)은 멈춘다. 정차(P)하면 새 도착 요약을 띄운다.
8. **넓은 배치(가로형)와 좁은 배치(세로형)의 기능은 같다.** 배치만 바뀐다.

## 2. 정보 구조

```
앱 시작
 ├─ 처음 실행이면: 시작 안내(3장) → 마을
 ├─ 보지 않은 도착 요약이 있으면: 도착 요약 → 마을
 └─ 그 밖: 마을

메인 탭 4개:  마을(홈) | 도감 | 기록 | 설정
겹쳐 뜨는 화면: 도착 요약(전체 화면), 운행 상세(전체 화면), 주민 상세(시트), 확률 안내(시트)
마을 안의 모드: 새 주민 배치, 꾸미기
디버그 빌드만: 진단, 디버그 메뉴 (설정 > 버전을 7번 누름)
```

- 앱이 보이는 상태에서 기어가 P가 되면, 어느 탭에 있든 도착 요약을 위에 띄운다.
- 뒤로 가기: 도착 요약 → 마을 / 시트 → 닫기 / 꾸미기 → "저장할까요?" 확인.

## 4. 화면별 설계

### 4.1 도착 요약 — 가장 중요한 화면 (PT 시연의 중심)

목적: "오늘 운전이 어땠고, 누구를 만났는지"를 3초 안에 보여 준다.

넓은 배치 (시안 화면 1):
```
┌──────────────────────────────────────────────────────────┐
│ ┌──────────────────────┐  11월 14일 토요일 오후 1:58 · 도착   │
│ │ Pleos Village        │  비 오는 날,                       │
│ │   우산은 와이퍼에서 왔어요 │  레이니가 따라왔어요  (Jua 제목)       │
│ │                      │  100  안전 점수 / 감점 없이 다녀왔어요 │
│ │     (큰 주민 그림)      │  [■■■■■■■■■■■■■■|■■■] 80점 막대    │
│ │   잔디 타원 + 꽃        │  ┌ 운전 시간 ······· 1시간 50분 ┐   │
│ │                      │  │ 오늘의 환경 ····· 비 · 가족 동승 │   │
│ │ No.01 · 확률 40%      │  │ 함께 탄 사람 ············ 4명 │   │
│ │ 레이니       새로 만남 │  └ 포인트 ················ +20 ┘   │
│ │            11월 14일 │  (?) 해삐는 이번엔 못 만났어요.       │
│ └──────────────────────┘  오늘 기회 1번 남음  [닫기][마을로 데려가기 →] │
└──────────────────────────────────────────────────────────┘
```
- 왼쪽 그림 칸: 만난 주민(선 3dp)과 그 주민의 소품 설명("우산은 와이퍼에서 왔어요" 등). 장식은 주민 종류에 맞춘다(비 = 빗방울, 밤 = 별, 가족 = 하트, 겨울 = 반짝이).
- 오른쪽: 도착 시각, 제목 2줄, 큰 점수 + 80점 막대, 값 카드(감점이 있으면 감점 줄을 맨 위에 warn 색으로), 못 만난 주민(실루엣 + "천장까지 N번"), 버튼.
- 도착 시각 뒤에 장소를 쓰지 않는다 (위치를 수집하지 않는다).

좁은 배치: 위에서 아래로 그림 칸 → 제목·점수·막대 → 값 카드 → 못 만난 주민 → 아래에 고정된 버튼 2개.

연출 순서 (전체 2.5초 이하, 화면을 누르면 바로 마지막 상태로 건너뜀):
1. 점수 숫자와 80점 막대가 0에서 점수까지 차오른다(0.8초). 막대에 80점 눈금을 표시한다. 80점 이상이면 민트, 미만이면 살구색.
2. 만난 주민이 통 튀어 오르며 나타나고 반짝이 1~2개가 생긴다(0.4초). 소품 설명이 함께 나타난다.
3. 포인트 숫자가 올라간다(0.4초).

상태별 표시 (SPEC 6.2와 맞춘다). 시안에 없는 상태도 같은 배치를 쓰고, 그림 칸에는 실루엣을 둔다:

| 상태 | 제목 / 그림 칸 / 아래 안내 |
|---|---|
| 만남·못 만남이 있음 | "비 오는 날, 레이니가 따라왔어요" / 만난 주민 / 못 만난 주민 줄. 2명을 만나면 둘째는 "○○도 만났어요" 줄 |
| 80점 미만 | "안전 점수 70점, 다음엔 80점을 넘겨 봐요" / 실루엣 / "80점 이상이어야 주민을 만날 수 있어요". 감점 줄은 값 카드 맨 위 |
| 10분 미만 운행 | "짧은 운행은 기록만 해요" / 실루엣 / 10분 기준 안내 |
| 하루 한도를 다 씀 | "오늘은 만날 기회 2번을 다 썼어요" / 실루엣 / "내일 다시 만나요" |
| 80점 이상이지만 해당 환경 없음 | "오늘은 새로 만날 수 있는 환경이 없었어요" / 아직 못 만난 주민 1명의 실루엣 / 그 주민의 환경 힌트 |
| 같은 운행의 두 번째 이후 정차 | 이번 정차에서 새로 판정한 주민만. 점수는 운행 전체 기준 |

버튼: [마을로 데려가기] = 새 주민이 있으면 마을의 배치 모드로, 없으면 마을로 간다. [닫기] = 이전 화면.

### 4.2 마을 (홈)

넓은 배치:
```
┌────┬─────────────────────────────────────────────────────┐
│ 🏘 │ 우리 가족 마을            주민 4명 · 포인트 214 · 기회 ●○ │
│마을 │ [이번 주 평균 94점] [80점 이상 6/6] [급한 조작 2번]       │
│ 📖 │ ┌─────────────────────────────────────────────────┐ │
│도감 │ │                                                 │ │
│ 📊 │ │       비스듬히 내려다보는 마을 (끌어서 이동,          │ │
│기록 │ │        두 손가락 또는 [+][-] 버튼으로 확대)          │ │
│ ⚙ │ │                                                 │ │
│설정 │ └─────────────────────────────────────────────────┘ │
│    │ [선택한 주민: 레이니 · 11월 7일, 비 오는 날]   [꾸미기]  │
└────┴─────────────────────────────────────────────────────┘
```
좁은 배치: 헤더 1줄(주민 · 포인트 · 기회), 주간 칩은 빼고(기록 탭에 있음), 마을이 화면 대부분, 아래 탭 바 바로 위에 [꾸미기].

상호작용:
- 주민이나 집을 누르면 말풍선(이름 · 만난 날 · 환경)이 뜬다. 말풍선의 "자세히" → 주민 상세 시트.
- 빈 땅은 점선 타일로 보여 준다. 처음에는 마을 회관만 있다(빈 마을): "첫 주민을 기다리는 자리".
- 주민은 정차 중이고 화면이 보일 때만 걸어 다닌다(초당 30프레임 이하). 주행 규제가 켜지거나 화면이 가려지면 멈춘다.
- **새 주민 배치 모드**: 도착 요약에서 들어오면, 빈 타일 하나를 추천해서 집을 미리 놓아 보여 준다. "여기에 둘까요?" [좋아요] [다른 곳]. [다른 곳]을 누르면 집을 끌어서 옮긴다. M1은 자동 배치만 한다.
- 주민이 늘면 땅이 넓어진다(6×6 → 8×8 → 10×10). 【팀 확인】
- **유휴 모드**: 메인 탭(마을·도감·기록·설정)에서 10초(`IDLE_TIMEOUT_MS`) 동안 화면을 건드리지 않으면 메뉴·카드·버튼을 모두 숨기고 마을 그림만 화면 가득 보여 준다(0.25초 페이드). 주민은 계속 걷는다(마을과 같은 규칙: 정차 중이고 화면이 보일 때만). 왼쪽 위에 지금 시각과 날짜를 둔다. 내비가 길 안내 중이면(NaviHelper `NavigationStatus.ROUTE_DRIVE` 또는 `RouteStateInfo.isRouting`) 왼쪽 아래 카드에 목적지, 남은 거리(`DestinationInfo.remainDistance`, m), 도착 예정 시각(지금 + 남은 시간), 남은 시간(`remainTime`/`DrivingState.duration`, 초)을 보여 준다. 아무 곳이나 누르면 보던 화면으로 돌아가고, 그 터치는 아래 화면에 전달하지 않는다. 도착 요약·운행 상세·꾸미기·시작 안내·디버그 화면, 그리고 시트나 확인 창이 떠 있을 때는 들어가지 않는다.

### 4.3 꾸미기 모드 (M2)

```
┌──────────────────────────────────────────────────────────┐
│ 꾸미기      ↶ 되돌리기  ↷ 다시          포인트 214   [ 완료 ] │
│ ┌──────────────────────────────────────────────────────┐ │
│ │  마을 (격자 선이 보임. 놓을 수 없는 칸은 빨간색)            │ │
│ └──────────────────────────────────────────────────────┘ │
│ [집] [길] [자연] [장식]    🌳 30   ⛲ 120   🌷 20   🔒 🏮 80  │
└──────────────────────────────────────────────────────────┘
```
- 아래 팔레트에서 아이템을 끌어서 놓는다. 끌기가 어려우면 아이템을 누르고 칸을 눌러도 놓인다.
- 놓인 아이템을 누르면 [옮기기] [돌리기] [보관함으로].
- 잠긴 아이템은 포인트로 연다("80포인트로 얻을까요?"). 실제 돈 결제는 넣지 않는다.
- 주민의 집도 옮길 수 있다. 주민 자체는 보관할 수 없다.
- [완료]를 눌러야 저장한다. 뒤로 가기를 누르면 "저장할까요?"를 묻는다.
- 좁은 배치: 팔레트를 아래 시트(화면 높이의 절반 이하)로 띄운다.

### 4.4 도감

```
┌────┬─────────────────────────────────────────────────────┐
│    │ 주민 도감                  6명 중 4명                  │
│    │ 안전 점수 80점 이상인 운행에서, 하루 2번까지 만날 수 있어요 │
│    │ [전체] [만남] [아직] [준비 중]                          │
│    │ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                  │
│    │ │ 카드  │ │ 카드  │ │ 카드  │ │ 카드  │                  │
│    │ └──────┘ └──────┘ └──────┘ └──────┘                  │
└────┴─────────────────────────────────────────────────────┘
```
- 카드 3종류:
  - 만남: 컬러 그림, 이름, 환경, 만난 날.
  - 아직: 실루엣, 환경, "아직 못 만났어요". 확률과 천장은 도감에 보여 주지 않는다(설정 > 확률 정보).
  - 준비 중: 점선 테두리, "출시 이후".
- 넓은 배치 4열, 좁은 배치 2열.
- 차량이 지원하지 않는 주민은 보여 주지 않는다.
- 카드를 누르면 주민 큰 카드(4.5).

### 4.5 주민 상세 (화면 가운데 큰 카드)

- 큰 그림, 이름, 한 줄 소개(예: "비 오는 날 안전하게 다녀온 기록").
- 만나는 환경. 아직 못 만난 주민은 "아직 못 만났어요" (확률·천장·못 만난 횟수는 보여 주지 않는다).
- 만난 주민이면 **"만난 날" 카드**: 날짜, 운전 시간, 안전 점수, 함께 탄 사람 수, 그날의 환경. (기획서의 N2: 이동을 기록으로 남김)
- [마을에서 보기] → 마을로 가서 그 주민을 가운데에 놓고 강조.
- **획득 카드**: 새 주민을 만나면 같은 큰 카드를 "새 주민을 만났어요!" 제목과 함께 띄운다(카드가 통 튀어 오르고 반짝이 1~2개). 버튼은 [닫기] [도감에서 보기]. 판정 로직(2단계) 전에는 디버그 메뉴의 "획득 카드 보기"로 띄운다.

### 4.6 기록 (M2)

탭 2개: **이번 주 | 운행**
- 이번 주: 카드 4개(평균 안전 점수, 80점 이상 운행 비율, 급한 핸들 조작·급제동 횟수, 2시간 넘는 운행에서 쉬어 간 비율). 각 카드에 지난주 대비. 그 아래 요일별 안전 점수 막대 7개(80점 선 표시).
- 운행: 운행 목록(날짜, 시각, 운전 시간, 점수 배지, 환경 아이콘, 만난 주민 얼굴). 누르면 **운행 상세** = 그 운행의 도착 요약을 연출 없이 다시 보여 준다.

### 4.7 설정 (M2)

- **이 차량에서 확인하는 항목**: 지원 여부 목록(예: 와이퍼 ✓, 하향등 ✓, 안전벨트 ✕). 지원하지 않는 항목은 "이 차량에서는 확인하지 않아요".
- **확률 안내**: 모든 주민의 환경, 확률, 천장 전체 표.
- **데이터**: "모든 기록은 이 차 안에만 저장돼요. 위치는 저장하지 않아요." [기록 지우기](확인 창).
- 시작 안내 다시 보기. 버전(디버그 빌드에서 7번 누르면 디버그 메뉴).

### 4.8 시작 안내 (처음 실행, 3장)

1. "운전하면 자동으로 기록돼요. 운전 중에는 화면이 보이지 않아요."
2. "안전 점수 80점 이상이면, 그날의 날씨와 함께 탄 사람에 맞는 주민을 만나요."
3. "주민이 모여 우리 가족 마을이 돼요."
[시작하기]. 건너뛰기 버튼을 둔다.

### 4.9 디버그 (디버그 빌드만)

진단 화면(있음)과 SPEC 8장의 디버그 메뉴. **시연 데이터 불러오기 버튼을 가장 위에** 둔다(PT 직전에 쓰기 쉽게).

## 6. 구현 구조 (Compose)

- Activity 1개와 `NavHost`. 경로: `village`, `dex`, `records`, `settings`, `arrival/{summaryId}`, `trip/{tripId}`, `decorate`, `onboarding`, `debug`. 주민 상세와 확률 안내는 `ModalBottomSheet`.
- `AdaptiveScaffold` 하나를 만든다: 넓으면 `NavigationRail`, 좁으면 `NavigationBar`.
- 화면마다 `ViewModel` + 불변 `UiState` + 사용자 이벤트. 화면 함수는 상태만 그린다.
- **`FakeRepository`**: 시안 데이터(주민 4명, 운행 10개, 모든 도착 요약 상태)를 넣는다. 도메인(M1)과 화면을 따로 개발하고, 모든 화면에 넓음/좁음 `@Preview`를 붙인다.
- 마을 그리기: `Canvas`에 타일, 집, 주민을 그린다. 화면 좌표 ↔ 타일 좌표 변환 함수 하나를 두고, 누르기 판정은 타일 좌표로 한다. 그림은 `ImageBitmap`으로 한 번만 불러온다. 걷기는 `withFrameNanos` 루프로 하고, 주행 규제가 켜지거나 화면이 가려지면 멈춘다.
- 주행 규제 상태를 CompositionLocal로 내려서, 모든 애니메이션이 한 곳의 값으로 같이 멈추게 한다.
- 문자열은 모두 `strings.xml`에 둔다.
